# Code

## Role

The Code verifies the complete universal Source Architecture contract using synthetic language shapes and the live Fortress source inventory.

## Execution

Tests construct canonical Project Filing and CCG fixtures, reuse documentation responsibilities, feed language-neutral observations, evaluate profile compositions, compare canonical bytes, and stress ten thousand artifacts without parsing real language syntax.

## State

All fixtures are deterministic in-memory values or bounded temporary repositories and retain no state between tests.

## Failure Semantics

Negative cases assert typed profile errors or exact Source Architecture conclusion kinds; unsupported observation remains explicit and never becomes favorable absence.

## Files

### [`source_architecture.rs`](../_code/source_architecture.rs)

Exercises responsibility, identity, content, profile, archetype, region, generated, verification, relocation, determinism, live inventory, and scale conformance requirements.

### [`python_lexical_observation.rs`](../_code/python_lexical_observation.rs)

Exercises exact SourceView, context, producer and mode correlation for compile-only Python lexical observations. Fixtures independently state scope and UTF-8 byte positions, and distinguish partial, invalid, unsupported and unavailable cases. Negative controls refuse mutated snapshots, contextual invalidity concealed by a later phase, noncanonical paths, control inputs, resolved target assertions, duplicate JSON fields, and byte, nesting, token count and token length budget exhaustion. Custody and output failures have separate allowed phase states. The controls admit retained reports only and launch no external process.

### [`python_import_observation.rs`](../_code/python_import_observation.rs)

Replays frozen CPython FileFinder expectations through immutable fixture bytes,
typed lexical admission and the production static resolver. The cases check
source and namespace selection, root and package precedence, scoped misses,
relative origin, attribute uncertainty and refusal to synthesize dynamic
imports. Separate controls reject forged pins, source or authority drift,
duplicate or unknown fields, protected paths, path ambiguity and oversized
inventories. Tests run without invoking Python or loading a fixture.
