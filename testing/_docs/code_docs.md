# Code

## Role

Exercise the Module responsibility through directly owned verification logic without becoming normative authority.

## Execution

Cargo invokes each explicit test target; the code loads direct fixtures or the governed repository, performs deterministic assertions, and terminates with process success or failure.

## State

Verification is stateless apart from process-local values and isolated disposable runtime repositories where a scenario requires filesystem behavior.

## Failure Semantics

A violated assertion or fixture-loading failure fails the test target and surfaces its exact subject; verification never suppresses production errors.

## Files

### [`audit_flow.rs`](../_code/audit_flow.rs)

Compiles the live distributed Intended BFG and proves the root-owned repository audit lifecycle spans the correct Module scope and participates in truthful audit rule evaluation.

### [`self_model.rs`](../_code/self_model.rs)

Checks root operational configuration, command registry agreement, complete contract resolution, and truthful non-certification state.

### [`semantic_qualification.rs`](../_code/semantic_qualification.rs)

Test-owned native observation target with a separate pure-reference port. Compares complete canonical cold, prepared, reused and foreign-context reconstructed products, findings, provenance and uncertainty; checks registered nonrecursive metadata neutrality. Flushes every original observation before the scorer can fail; malformed inputs have separately labeled error-port equivalence.

### [`semantic_qualification.py`](../_code/semantic_qualification.py)

Owns independent fixture admission, primitive-reference comparison, all 86 preregistered candidate outcomes, 384 directed source-replacement contrasts, separate site/claim/path counts and exact qualification bindings. Active/raw observations remain in bounded external OPS-retained storage, survive failures and build cleanup, and never become application evidence. Replays disclose consumed holdouts. Only compact passing metadata is selected into a generation.

### [`qualification_controls.py`](../_code/qualification_controls.py)

Eight independent harness countermodels reject all-absence/all-violation answers, missing witnesses/proofs/cases, incorrect test-only enforcement, unequal ports/metadata and duplicate or foreign observations. They are scorer sensitivity controls, not production-code mutation statistics or held-out candidate evaluations.
