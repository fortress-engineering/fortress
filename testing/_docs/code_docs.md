# Code

## Role

Exercise the Module responsibility through directly owned verification logic without becoming normative authority.

## Execution

Cargo invokes each explicit test target; the code loads direct fixtures or the governed repository, performs deterministic assertions, and terminates with process success or failure.

## State

Verification is stateless apart from process-local values and isolated disposable runtime repositories where a scenario requires filesystem behavior.

## Failure Semantics

A violated assertion or fixture-loading failure fails the test target and surfaces its exact subject; verification never suppresses production errors.

## Files

### [`audit_flow.rs`](../_code/audit_flow.rs)

Compiles the live distributed Intended BFG and proves the root-owned repository audit lifecycle spans the correct Module scope and participates in truthful audit rule evaluation.

### [`self_model.rs`](../_code/self_model.rs)

Checks root operational configuration, command registry agreement, complete contract resolution, and truthful non-certification state.

### [`semantic_qualification.rs`](../_code/semantic_qualification.rs)

Test-owned native observation target with a separate pure-reference port. Compares complete canonical cold, prepared, reused and foreign-context reconstructed products, findings, provenance and uncertainty; checks registered nonrecursive metadata neutrality. Flushes every original observation before the scorer can fail; malformed inputs have separately labeled error-port equivalence.

### [`semantic_qualification.py`](../_code/semantic_qualification.py)

Owns independent fixture admission, primitive-reference comparison, all 86 preregistered candidate outcomes, 384 directed source-replacement contrasts, separate site/claim/path counts and exact qualification bindings. Active/raw observations remain in bounded external OPS-retained storage, survive failures and build cleanup, and never become application evidence. Replays disclose consumed holdouts. Only compact passing metadata is selected into a generation.

### [`qualification_controls.py`](../_code/qualification_controls.py)

Eight independent harness countermodels reject all-absence/all-violation answers, missing witnesses/proofs/cases, incorrect test-only enforcement, unequal ports/metadata and duplicate or foreign observations. They are scorer sensitivity controls, not production-code mutation statistics or held-out candidate evaluations.

### [`verify_bundle.py`](../_code/verify_bundle.py)

Standalone offline public consumer implemented with Python's standard library. Copy this single file to a consumer machine and run `python -I -B verify_bundle.py BUNDLE --predicate-type OWNER_URI`. It has no Fortress imports, Rust types, network client or project execution path. It independently checks JCS, byte identities, required artifacts, graph coherence, static and provider premises, exact bindings and conditional ALL/ANY profile replay. Integrity, conditional replay, unauthenticated provenance, unproven semantics/execution and independently supplied current references are separate fields. Exit 0 means complete consistent integrity with no detected supplied-reference mismatch, never assurance approval; exit 1 means incomplete or stale; exit 2 means invalid/unsupported input.

### [`portable_controls.py`](../_code/portable_controls.py)

Independent truth tables, RFC canonicalization facts, public parser/provider vectors and archive/path/resource attacks. Native regression tests feed original Rust-produced assessment records to this separate consumer and compare all declared outcomes. Actual consumer and development-machine performance observations remain diagnostic research records, separate from certification thresholds.

### [`security_controls.py`](../_code/security_controls.py)

Runs independent malformed JSON/ZIP, preallocation, retained-container, path ambiguity and mutation controls, plus the installed Python operational-reader and exact-source qualification integrity controls. It never extracts archives, contacts services or executes repository code. The canonical issuer retains its compact results through OPS and requires this gate in addition to every established gate.

### [`performance_probe.rs`](../_code/performance_probe.rs)

Explicit prebuilt observer over existing production APIs. Separates PSM construction from hashing, and governed query loading from 100 complete requests per method. Resident experiments compare canonical members with independent cold reconstruction, eviction fallback and cancellation, then compare source and protected-authority candidate results with independent cold evaluation. An equal error code remains an error comparison, not canonical success. Accounted resident bytes are conservative admission charges, not measured RSS.

### [`performance_runner.py`](../_code/performance_runner.py)

Verifies the prebuilt observer's exact bytes, input source before and after execution, safe external destinations and bounded process duration. It never compiles, initializes governance or executes project code implicitly. New disposable synthetic fixtures contain only Cargo metadata and Rust source. Their bounded, relative-path inventory digest identifies native workload bytes in a separate domain. Each is evaluated in two independent PSM processes. An explicit governed root uses the normal certificate source fingerprint for the separate resident experiment. A small independently owned supervisor root excludes unrelated compiler-store traversal from diagnostic timing. Preparation and supervision costs remain reported separately. Cancellation and uncertain descendants retain recovery state rather than asserting cleanup.

### [`performance_qualification.py`](../_code/performance_qualification.py)

Composes and checks the public JCS derivative record using the independent portable consumer. Version 2 binds the exact selection manifest and evidence for comparisons, restorations, the separate lifecycle run and both differential corpora. It requires exact-source references and an explicitly recorded unfiltered suite. Version 1 records retain their historical population. A consumer must independently inspect the referenced certificate and execution reports. Successful checking establishes record integrity.

### [`performance_controls.py`](../_code/performance_controls.py)

Exercises streaming read/copy limits, source drift, exact preimage preservation, incomplete or tampered projection sets, deterministic source generation, retained correctness references and bounded process supervision. Percentile controls require at least 20 samples for p95 and 100 for p99. No numerical timing target is a test condition.

Diagnostic comparisons must pin implementation and workload identities independently, record machine/toolchain conditions, include compilation and preprocessing separately, disclose competing workloads and preserve failed observations. Compare unchanged reference and proposed algorithms over the same frozen source. A selected microbenchmark, cached query or smaller population cannot establish end-to-end speedup. The registered independent cold campaign deliberately repeats expensive work and is distinct from ordinary production issuance. RSS, conservative admission accounting, compiler bytes, retained evidence and free storage are different measurements. Synthetic scaling, single-host variance and incomplete resource-limited experiments limit generalization.
