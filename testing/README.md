# Fortress Testing

## Purpose

This verification Module proves the bootstrap-governance and complete audit Features introduced directly by the Fortress root Module and owns shared replayable regression fixtures and the independently grounded automated qualification protocol.

## Responsibility

Validate the root-owned self-model, command-declaration agreement, complete contract resolution, derived-certification authority boundary, and cross-subsystem repository audit lifecycle without claiming evidence for descendant Features. Pin exact source and policy controls that descendant tests replay without granting production exemptions.

## Scope

### Includes

Rust verification code whose claims map exclusively to root-owned bootstrap-governance and Fortress audit requirements while using descendant capabilities where execution requires them.

### Excludes

Requirements owned by Engine, CLI, or any deeper Module; normative standard meaning; production implementation; and application execution evidence. Active logs and bulk observations stay external; only compact qualified tool metadata is published through the control generation.

## Guarantees

Self-verification is deterministic, operates on the declared repository root, and authors only explicit obligation bindings; Certification alone reconciles those bindings with current execution evidence.

The automated semantic envelope is fixed before candidate scoring: 86 cases (76 required controls, 28 selected holdouts), two original public file scopes and 384 source-replacement relations among 64 cases. Independent primitive semantics and pinned API/language sources establish expected outcomes; Fortress output never supplies its own answer. All unknown, nonapplicable, malformed, unsupported, advisory, ALLOW and undeclared outcomes remain in their denominators. Source sites, claims and causal observation paths are separate; mutations and fan-in are not independent samples. First observations and failures are retained, and all later observations are disclosed replays of exposed holdouts. Automated conformance is limited to this envelope, with no population accuracy, human review, confidence or independent external assurance claim. The pure reference helper has deliberately authored no-write/no-spawn policies and a real nonempty Feature/local Testing boundary; unrelated I/O responsibilities remain undeclared.

Cross-effect negatives exercise explicit accepted research primitive bounds only for exact frozen literal-borrow and fresh-command sources. These bounds are assumptions under the existing summary contract, not certified Standard-library facts. Their references remain in results, and the same sources retain uncertainty with default partial summaries. Public scopes receive no synthetic premises. The driver retains all earlier failures and incomplete observations; later corrected runs are requalification of exposed holdouts.
