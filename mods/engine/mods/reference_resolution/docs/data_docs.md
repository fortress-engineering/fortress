# Data

## Role

The Module owns the draft relocation-transparency rule and the canonical schema for its focused derived resolution projection.

## Origin

Both records are specification-authored from the stable-identity and explicit-resolution-boundary doctrine introduced by this Module.

## Semantics

The rule governs understood cross-Module references; the schema represents current Module locations, classified references, registered physical boundaries, source CCG identity, and deterministic summary counts without duplicating the CCG.

## Validity

Rule and schema identities must remain registry-unique, paths must be portable and canonical, enums are closed, and the derived projection must bind the exact source CCG digest and resolver semantic version.

## Lifecycle

Compatible clarifications retain schema v1; incompatible representation changes require a new schema identity. A changed CCG or understood projection input requires regeneration rather than manual artifact editing.

## Files

### [`reference_rule.json`](../data/reference_rule.json)

Defines draft rule REPO-REFERENCE-001 for relocation-transparent governed references.

### [`resolution_index_schema_v1.json`](../data/resolution_index_schema_v1.json)

Defines the focused CCG-bound derived projection from stable Module identity to current repository location and registered physical boundaries.
