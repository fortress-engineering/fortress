# Source Architecture

## Purpose

Establish one language-neutral architectural model for governed source artifacts between physical Project Filing placement and language-specific File Content Profiles.

## Responsibility

Compile canonical authored file responsibility, Project Filing ownership, snapshot-bound observation facts, and registered profile semantics into deterministic Source Artifact Model v1, then evaluate only justified file-level structural coherence.

## Scope

### Includes

Universal semantic regions, truthful coverage states, language-profile and archetype contracts, generated-source provenance, stable semantic references, deterministic projection, and SOURCE-PROFILE-001/SOURCE-ARTIFACT-001 evaluation.

### Excludes

Rust-specific file archetypes or ordering, universal one-X-per-file rules, source reparsing, natural-language/code matching, automatic rewriting, and deep value/state/effect/security/environment reasoning.

## Relationships

### [Contract Coherency](../contract_coherency/README.md)

**Types:** `depends_on`

Supplies stable Module, Feature, Requirement, and verification identities without turning file architecture into architectural authority.

### [Finding Model](../finding_model/README.md)

**Types:** `depends_on`

Source Architecture emits every structural contradiction through the shared canonical Finding Model.

### [Implementation Observation](../implementation_observation/README.md)

**Types:** `depends_on`

Snapshot-bound observations can contribute lightweight region evidence without becoming architectural intent.

### [Program Semantics](../program_semantics/README.md)

**Types:** `depends_on`

Existing symbols, nominal declarations, calls, and state-place facts are referenced where available rather than parsed or copied.

### [Project Model](../project_model/README.md)

**Types:** `depends_on`

The canonical Project Filing model remains authoritative for Module ownership, Code membership, and filesystem validity.

## Guarantees

Source Artifact identities derive from stable owning Module identity and Module-local path, exact bytes remain independently content-addressed, unsupported observations never become absence, and no universal language syntax or one-declaration-per-file doctrine is introduced.
